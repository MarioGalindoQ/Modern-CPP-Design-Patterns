# std::variant (MODERN C++17 FEATURE)
**Author:** Mario Galindo Queralt, Ph.D.

## Intent
To provide a type-safe union that can hold exactly one value from a predefined 
set of heterogeneous types, managing the lifecycle of the contained object 
automatically. It enables "Value Semantics" for polymorphic behavior without 
the overhead of pointers or virtual tables.

## The Problem
In older C++, creating heterogeneous collections (e.g., a list containing 
ints, strings, and custom objects) required either:
1. Pointers to a common base class (Polymorphism + Heap Allocation).
2. Unsafe C-style 'union' structures, which cannot safely hold objects with 
constructors or destructors (like std::string) without complex manual 
management.
3. 'void*' pointers, which completely destroy type safety.

## The Solution
C++17 introduced 'std::variant', a standard library feature that acts as a 
"Sum Type". 
- It knows exactly which type it currently holds.
- It is type-safe: you cannot extract a type that is not currently active.
- It automatically calls the constructor, copy/move operators, and destructor 
of the active object, making it safe to use with complex C++ classes.
- It stores the object "in-place" (on the stack or directly inside the 
container), avoiding costly heap allocations (no 'new' or 'delete').

## Our Examples
This folder contains two different approaches to using variants:

### 1. VariantSimple (Lifecycle & Memory Tracking)
This program demonstrates how 'std::variant' manages memory and types:
- **Size Comparison:** We print the 'sizeof' each component versus the variant 
itself to prove that a variant is roughly the size of its largest member 
plus a small tag (index).
- **Memory Tracking:** We use a custom 'Logger' class implementing the "Rule of 
Seven" (DC, CC, MC, CA, MA, De, PC) to visually trace how the variant safely 
moves and destroys objects behind the scenes.
- **The Modern Visitor:** We process a stack of variants using a Functor 
(a struct with overloaded operator()), demonstrating stateful visitors 
without virtual inheritance.

### 2. VariantValueClone (Modern Prototype Pattern)
This program demonstrates a radical shift in design from the traditional 
Prototype Pattern (see 32_CRTP/03_PolymorphicClone):
- **Automatic Cloning:** Instead of implementing a 'clone()' method or using 
the CRTP Mixin, we rely on "Value Semantics". 
- **Deep Copy by Default:** We show that cloning a heterogeneous collection 
is as simple as 'clones = originals'. The 'std::variant' automatically 
dispatches the correct copy/move constructors for each contained type.
- **Efficiency:** We analyze the importance of 'noexcept' in move constructors 
to allow 'std::vector' to optimize memory reallocations without falling 
back to expensive copies.

## Relation to other Design Patterns
While not a GoF pattern itself, 'std::variant' is the modern foundation for:
- **The Modern Prototype Pattern:** Performing deep copies of heterogeneous 
  objects without pointers or 'clone()' methods, see 02_VariantValueClone/.
- **The Modern Visitor Pattern:** Handling polymorphism and dispatching 
  without virtual tables, see 28_Visitor/*/*Visitor_Modern_Variant/.
- **Finite State Machines:** Representing different states as variant types, 
  see 25_FiniteStateMachine/03_CDPlayer_Variant/.
- **Command Pattern:** Encapsulating requests as variant objects, see 
  19_Command/02_Modern_Variant/.
- **Error Handling:** Returning a variant containing either a Result or 
  an Error (the 'Expected' idiom), see 34_ErrorHandling/01_ErrorHandling_Variant/.
