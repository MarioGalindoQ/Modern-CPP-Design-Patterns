# PROTOTYPE PATTERN (CREATIONAL)
**Author:** Mario Galindo Queralt, Ph.D.

## Intent
To specify the kinds of objects to create using a prototypical instance, 
and create new objects by copying this prototype. This pattern is also 
frequently referred to as the "Virtual Constructor" idiom in C++.

## The Problem
Creating a new instance of an object from scratch can be a heavy, resource-
intensive process. If you already have an object that has been fully 
configured (e.g., loaded from a file, initialized with complex data), 
it is often more efficient to copy that object rather than reconstructing 
it from zero.

Furthermore, in C++, we often need to clone objects through a base class 
pointer without knowing their concrete type, but the language does not 
provide built-in virtual constructors.

## The Solution
The Prototype pattern suggests copying an existing object (the prototype) 
rather than creating a new instance. The newly copied object inherits 
the entire state of the original.

This approach is highly effective in scenarios where
1. Object creation is a "heavy" or costly process.
2. You need to create objects at runtime without being bound to their 
concrete classes.
3. You want to avoid the "subclassing" explosion that factories might 
sometimes cause.

## Our Examples
This folder illustrates the evolution of the Prototype implementation in C++:

1. **01_Traditional/:**
The classic GoF implementation. It demonstrates the "Virtual Constructor" 
idiom where every derived class must manually override a 'clone()' method. 
While effective, it leads to significant boilerplate code.

2. **02_Deducing_this/ (Modern C++23):**
The most advanced and cleanest implementation. It uses C++23 **"Deducing This"** 
(Explicit Object Parameters) to implement the cloning logic once in a 
base Mixin. By using 'this auto self', the compiler automatically captures 
the derived type, eliminating manual overrides and the need for the CRTP idiom.

## Technical Evolution (Comparison)
C++ offers three main ways to automate or implement this pattern:

- **Traditional (Example 01):** Manual 'override clone()'. High maintenance, 
  but very explicit.
- **CRTP (see 32_CRTP/03):** Automated cloning via 'Cloneable<Derived>'. 
  Eliminates boilerplate but introduces complex circular template dependencies.
- **Deducing This (Example 02):** Automated cloning via a simple Mixin and 
  'this auto self'. It is the modern C++23 replacement for CRTP, offering 
  the cleanest syntax and absolute type safety.

## Key Benefits
- **Efficiency:** Saves costly resources by avoiding redundant initialization.
- **Dynamic Configuration:** Allows the system to work with objects of any 
  concrete class without being tightly coupled to them.
- **Reduced Boilerplate:** Modern versions (C++23) allow injecting cloning 
  capabilities into entire hierarchies with a single method definition.
